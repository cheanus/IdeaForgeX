# Neo4j 图数据模型

## 1. 节点

### Inspiration（方法灵感）

代表一个被抽象化、泛化后的方法模式/技术思想。

| 属性 | 含义 |
|---|---|
| id | 唯一标识，`insp-{uuid}` |
| 粒度 | 0=纯认知操作, 1=方法族, 2=技术方案, 3+=具体变体 |
| 核心描述 | 该粒度的描述文本，也是 embedding 源 |
| 向量 | embedding 输出，驱动向量检索 |
| 前提条件 | 适用场景 |
| 操作步骤 | 转化为创新的步骤 |
| 已知实例 | 体现该模式的论文，可缺省 |

### Question（研究问题）

代表一个未被完全解决的研究缺口/问题。

| 属性 | 含义 |
|---|---|
| id | 唯一标识，`q-{uuid}` |
| 核心描述 | 一句话描述，也是 embedding 源 |
| 向量 | embedding 输出 |
| 问题类型 | 理论缺口 / 工程瓶颈 / 评估缺失 / 跨领域空白 |
| 当前现状 | 已有方法解决的部分 |
| 未解决部分 | 具体未解决的问题 |

### 节点更新

训练时 LLM 可对已有节点进行增量属性修改。可更新的字段：`粒度`、`前提条件`、`操作步骤`、`已知实例`（Inspiration）；`问题类型`、`当前现状`、`未解决部分`（Question）。不可更新：`id`、`核心描述`、`向量`。

## 2. 边

### 灵感精化边（INSP_REFINES）

有向，低粒度→高粒度。同一精化链上节点同属一个方法概念，按粒度递增串联。

### 灵感组合边（INSP_COMBINES）

无向。连接两个不同方法概念的 Inspiration，表示两者结合可产生新方向。

### 灵感问题边（INSP_QUESTION）

无向。连接 Inspiration 和 Question，表示某方法可驱动某问题的解决。

### 问题组合边（QUESTION_COMBINES）

无向。连接两个不同 Question，其交集定义了一个新的、更有趣的研究缺口。

## 3. 向量索引

在 `Inspiration.向量` 和 `Question.向量` 上各建立一个余弦相似度 HNSW 向量索引，维度由 embedding 模型配置决定。启动时幂等创建。

## 4. 论文库

已训练论文 ID 集合，仅用于去重。不存向量。
